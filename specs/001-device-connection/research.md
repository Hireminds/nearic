# Обоснование технических решений

## Платформа и установка

ESP-IDF v5.5.6, ESP32-S3, Espressif BOX-3 BSP 3.2.1 и LVGL 9.4.0.
Официальный BSP покрывает варианты контроллера дисплея. Один проект CMake и
одна целевая конфигурация обеспечивают воспроизводимую сборку.
[ESP-IDF](https://github.com/espressif/esp-idf/releases/tag/v5.5.6) ·
[BSP](https://components.espressif.com/components/espressif/esp-box-3/versions/3.2.1/readme)

USB используется для первой установки образа и восстановления. Для настройки
с телефона предлагаем SoftAP с WPA2-Personal и локальную страницу на BOX. Это
позволяет пройти первый запуск из браузера. Пароль временной сети уникален для сессии и виден
на экране BOX. После успешной настройки или истечения сессии BOX закрывает
точку доступа. Проверяем подключение при отсутствии интернета на временной
сети. Адрес страницы отображается для ручного открытия. BLE имеет смысл при
наличии мобильного приложения. [Настройка Wi-Fi в ESP-IDF](https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32s3/api-reference/provisioning/provisioning.html)

Адрес Nearic Service входит в сборку. После получения доступа в интернет BOX
сам устанавливает исходящее соединение с VPS. Сервер подтверждает регистрацию
по коду с физического экрана. Учётные данные Wi-Fi и самого BOX хранятся на
отдельном разделе NVS и сохраняются при OTA.

## Устройство, сервис и клиент

Для подключения, статуса и сведений об обновлении предлагаем обмен по HTTPS.
Короткий опрос позволяет реализовать первый сценарий без входящего соединения
или отдельного канала на устройство. Протокол операций отделён от транспорта.
Голос и экран смогут использовать собственный поток в следующей версии.
Общую модель маршрутизации и статус операции используем во всех клиентах.

В Codex OAuth открывает доступ интеграции. Явный вызов привязки из разговора
добавляет адресацию. В исходниках Codex 0.162.0 Core формирует метаданные
`threadId` и `sessionId` для вызова MCP. Для разговора нужен `threadId`.
Метаданные маршрутизируют операции, а разрешение определяется учётной
записью, подтверждением владельца и grant. Работа с плагином Desktop и
удалённым CLI проверяется сквозным прогоном их фактических версий.

[Метаданные Codex MCP](https://github.com/openai/codex/blob/rust-v0.162.0/codex-rs/core/src/mcp_tool_call.rs#L1407-L1436) ·
[OAuth в Desktop и CLI](https://learn.chatgpt.com/docs/extend/mcp?surface=desktop)

## OTA и восстановление

Используем две области приложения, отдельный `otadata` и управление откатом
ESP-IDF. USB устанавливает исходный образ в `ota_0` с очищенным `otadata`.
На устройстве подтверждаем рабочую версию. После установки следующей версии
проверяем чтение настроек, дисплей и запуск сетевого стека до подтверждения.
Недоступность VPS при загрузке сама по себе не считается дефектом образа.

Проверка подписи обновления в ESP-IDF без записи eFuse сохраняет USB-восстановление.
Первый релиз тоже подписывается. Закрытый ключ остаётся у выпускающей стороны.
[OTA и откат](https://docs.espressif.com/projects/esp-idf/en/release-v5.5/esp32s3/api-reference/system/ota.html) ·
[Проверка подписи образа](https://docs.espressif.com/projects/esp-idf/en/release-v5.5/esp32s3/security/secure-boot-v2.html#signed-app-verification-without-hardware-secure-boot)
