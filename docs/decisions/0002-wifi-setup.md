# ADR 0002. Настройка Wi-Fi через временную сеть BOX

Статус — предложено. Связанная [спецификация](../../specs/001-device-connection/spec.md#первое-включение-и-wi-fi).

## Контекст

Владелец подключает уже прошитый BOX с телефона до выхода в интернет и входа в Nearic.
При смене Wi-Fi сохраняются регистрация устройства и активный разговор.

## Решение

BOX включает временную сеть WPA2-Personal, создаёт пароль для новой сессии
и показывает на экране реквизиты и адрес страницы. Страница и все ресурсы
загружаются с BOX. Маршруты настройки доступны только через временную сеть.
После успеха, отмены или истечения сессии BOX закрывает сеть и очищает временные данные.

BOX проверяет новую сеть в режиме AP+STA и сохраняет рабочую конфигурацию после
получения IP. Пока идёт проверка, кандидат хранится в памяти. Ошибка или отмена
позволяет снова использовать последнюю сохранённую сеть. Доступ BOX хранится
отдельно. Подключение к Nearic отображается отдельным состоянием после настройки Wi-Fi.

ESP32-S3 использует один канал для двух интерфейсов. Во время проверки другой
домашней сети телефон может переподключиться к BOX. В активной сессии страница
показывает состояние текущей попытки. Завершение видно на экране BOX.

Сетевой модуль включает AP+STA после настройки WPA2 и выдаёт реквизиты сессии
после запуска DHCP-сервера. Пароль из 16 случайных символов генерируется при
запущенном Wi-Fi и хранится в памяти до закрытия сессии. Во время пробы
перезапускается и радио точки доступа, поэтому телефон может вернуться по тем
же реквизитам. При закрытии модуль выключает точку доступа и возвращает режим
STA. Локальный обработчик должен принимать запросы только через интерфейс точки
доступа. [Генератор случайных чисел ESP32-S3](https://docs.espressif.com/projects/esp-idf/en/v5.5.6/esp32s3/api-reference/system/random.html#enabling-rf-subsystem)

### Локальный HTTP

Слушающий сокет привязывается к интерфейсу точки доступа через `SO_BINDTODEVICE`
до начала приёма соединений. Ошибка привязки завершает запуск локального сервера.
Для ESP-IDF v5.5.6 используем изменение Espressif, которое добавляет параметр
`httpd_config_t.if_name` поверх поддержки в lwIP. В рабочей сборке применяем
изменение к копии компонента `esp_http_server` в каталоге сборки.
[Изменение HTTP-сервера Espressif](https://github.com/espressif/esp-idf/commit/7e2e09c15c29f50495db5d677135beca30343dd5)

При остановке радио ESP-IDF убирает интерфейс из lwIP. При следующем запуске
имя может измениться. Сетевой модуль останавливает локальный сервер перед
остановкой радио. После запуска точки доступа и DHCP сервер заново получает
имя интерфейса через `esp_netif_get_netif_impl_name()` и привязывает сокет.
Состояние попытки и реквизиты сохраняются до конца сессии. После возвращения
в сеть телефон может запросить ход той же попытки.
[Жизненный цикл интерфейса ESP-IDF](https://github.com/espressif/esp-idf/blob/v5.5.6/components/esp_netif/lwip/esp_netif_lwip.c#L1181)

### Сессия настройки

Сессия действует 10 минут после запуска временной сети. Отмена с BOX и истечение
останавливают текущую пробу, пока запись проверенного профиля ещё не началась.
При завершении модуль очищает временные реквизиты и выключает сервер и точку
доступа. Повторный запуск создаёт новые реквизиты и новый список сетей.

`GET /api/wifi` возвращает состояние, результат последней пробы (`-1` до пробы,
затем значение `nearic_wifi_trial_result_t`) и найденные сети. Поле `ssid_hex`
сохраняет байты имени сети, а `id` действует до следующего сканирования.
`POST /api/wifi/scan` запрашивает обновление списка. В `POST /api/wifi/connect`
браузер передаёт `id` в `X-Nearic-Network` и пароль в теле запроса. Оба POST
принимают `application/octet-stream`. Ответ `202` означает, что BOX принял
действие. Если выбранная сеть требует пароль, пустой пароль сразу даёт состояние
повтора с ошибкой аутентификации без перезапуска радио. В активной сессии
устаревший `id` и другая операция дают `409`. После переподключения браузер
читает состояние с BOX.
Пароль для сети BOX выдаётся только локальному экрану. HTTP требует `Host`,
соответствующий адресу точки доступа, и исключает результаты из кэша браузера.

Если точка доступа не отвечает на аутентификацию или ассоциацию, BOX повторяет
подключение один раз в пределах той же пробы. Ошибка пароля завершает пробу
и возвращает состояние для повтора с телефона.
[Параметры подключения ESP-IDF](https://docs.espressif.com/projects/esp-idf/en/v5.5.6/esp32s3/api-reference/network/esp_wifi.html#_CPPv416esp_wifi_connectv)

В ESP-Emulator 1.2.0 для защищённой сети проверены пустой, затем неверный и
верный пароль. Идентификатор сети остался действующим в той же сессии. После
верного пароля BOX получил IP, сохранил профиль и закрыл временную сеть.

### Хранение профилей

После получения IP сетевой модуль записывает профиль в один из двух ключей
`nearic_cfg`. При смене сети модуль освобождает более старый слот, записывает
туда следующее поколение и сверяет запись повторным чтением. При запуске BOX
выбирает целый профиль с наибольшим поколением. Пока запись прервана, остаётся
доступен прежний профиль. После полной записи прошивка может восстановить уже
проверенную новую сеть даже при отключении питания до подтверждения на экране.
Если флеш-память вернула ошибку после начала записи, модуль сообщает, что
результат записи неизвестен, и пробует прежнюю сеть в текущем запуске.
Профили из ранних сборок и USB-ключи переносятся после подтверждённого подключения.

[Реализация NVS в ESP-IDF v5.5.6](https://github.com/espressif/esp-idf/blob/v5.5.6/components/nvs_flash/src/nvs_storage.cpp#L390)

## Альтернативы

Настройка по BLE зависит от мобильного приложения или поддержки Bluetooth в браузере.
Локальная страница работает через системный Wi-Fi и обычный браузер. Для автоматического
открытия страницы через captive portal нужна проверка поведения конкретных ОС.
В первой итерации адрес страницы показывается на экране BOX.

## Проверка

На iOS и Android проверяем локальную страницу без интернета, неверный пароль,
повторный вход в активную сессию и смену сети на другой канал. Перезапуск до сохранения
новой конфигурации должен восстановить последнюю рабочую. Этапы описаны в
[сценарии приёмки](../../specs/001-device-connection/quickstart.md#первый-запуск-с-телефона).

Диагностический образ ESP32-S3 на ESP-IDF v5.5.6 с изменением HTTP-сервера
проверен в ESP-Emulator 1.2.0. При одновременно активных интерфейсах сервер
настройки ответил через временную сеть BOX. Через домашнюю сеть контрольный
сервер ответил с адреса STA, а сервер настройки отклонил соединение. С неверным
именем интерфейса запуск сервера завершился ошибкой.

Прогон сетевого модуля собрал копию HTTP-компонента через CMake Nearic.
После пробы недоступной сети, восстановления и подключения к домашней сети
сервер каждый раз привязался к новому интерфейсу AP. Запрос через временную
сеть прошёл после перезапусков. Через STA сервер отклонил соединение.
После закрытия сессии порт настройки закрылся, контрольный сервер ответил по STA.
Сценарий со страницей настройки проверяем на физическом BOX и телефоне.
В том же прогоне прошла полная сборка BOX. Контрольные суммы исходников HTTP
в SDK и файла зависимостей прошивки совпали до и после сборки.

В прогоне контроллера виртуальный телефон получил список сетей, обновил его
и получил отказ на устаревший `id`. После неверного пароля он вернулся в ту же
сессию, прочитал ошибку и отправил верный пароль. После одного тайм-аута
ассоциации BOX повторил запрос, получил IP, сохранил профиль и закрыл AP.
Отмену, истечение в середине пробы и истечение во время приёма пароля проверили
на стенде с управляемым временем и подменой драйвера.
